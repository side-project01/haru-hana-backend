## 1. 제품 개요

### 1.1 한 줄 정의
> 매일 하나의 질문에 답하고, 그 답을 감성 카드로 만들어 보관하며, 같은 질문에 답한 타인의 생각을 엿보는 **하루 1회·익명 기반 셀프 리플렉션 서비스**.

### 1.2 배경 / 문제 정의
- SNS 피로감이 커지면서 "전시용 기록"이 아닌 **나를 위한 가벼운 기록**에 대한 수요가 있다.
- 일기·저널링은 진입 장벽(무엇을 쓸지 막막함, 매일 쓰는 부담)이 높다.
- 본 제품은 **질문을 대신 던져주고(부담 제거)**, **하루 1회로 제한해(과몰입 방지)**, **결과물을 카드로 시각화(작은 성취감)**, **타인 답변 노출로 연결감(고립감 완화)**을 제공한다.

### 1.3 핵심 가치 제안 (Value Proposition)
| 사용자 Pain | 본 제품의 해결 |
|---|---|
| 뭘 써야 할지 모르겠다 | 매일 큐레이션된 질문 1개 제공 |
| 매일 쓰는 게 부담스럽다 | 하루 1회 제한 → "오늘 치 완료" 명확한 종료감 |
| 기록이 무미건조하다 | 배경 선택형 감성 카드로 시각화 |
| 혼자 쓰는 게 외롭다 | 같은 질문에 답한 타인 답변 1개 노출 |

## 2. 목표 및 성공 지표

### 2.1 비즈니스/제품 목표
1. 매일 돌아오는 **습관형 리텐션** 제품으로 자리잡는다.
2. 가입/로그인 없는 **초저마찰 온보딩**으로 첫 답변 전환율을 극대화한다.

### 2.2 핵심 지표 (North Star & KPI)
| 구분 | 지표 | 정의 | MVP 목표(가설) |
|---|---|---|---|
| **North Star** | DAU 중 답변 완료율 | (오늘 답변 제출자) / (오늘 진입자) | 40%+ |
| 획득 | 첫 답변 전환율 | 최초 진입자 중 1회 이상 답변한 비율 | 35%+ |
| 리텐션 | D1 / D7 재방문율 | 익명 식별자 기준 | D1 25% / D7 10% |
| 참여 | 타인 답변 조회율 | 카드 완성자 중 타인 답변 본 비율 | 50%+ |
| 품질 | 욕설/부적절 제출 차단율 | 필터 차단 / 전체 제출 | 측정·관리 |

> **로그인이 없으므로 식별 단위는 "익명 식별자(쿠키/디바이스 토큰)"** 임을 모든 지표 정의에 명시한다. 동일인이 기기를 바꾸면 별도 사용자로 집계되는 한계를 분석 시 감안한다.

## 4. 핵심 정책 (Product Rules)

기획의 뼈대가 되는 규칙. 개발/디자인은 아래 정책을 단일 진실 공급원(SSOT)으로 삼는다.

> **확정 결정사항**: 서비스 기준 날짜·하루 1회 판정·질문 전환의 기준 타임존은 **KST(한국 시간) 자정 고정**이다. 사용자 로컬 시간과 무관하게 동일 시점에 일괄 적용한다.

| ID | 정책 | 상세 | 근거 |
|---|---|---|---|
| **P1** | 하루 1회 답변 | 같은 날(서비스 기준 날짜) 답변 기록이 있으면 재작성 불가. 재진입 시 질문 화면을 건너뛰고 **④ 내 카드(완료 상태)로 바로 이동**한다. | 과몰입 방지·종료감 제공 |
| **P2** | 무로그인 / 익명 | 별도 가입 없이 익명 식별자 단위로 동작. | 진입 마찰 최소화 |
| **P3** | 1일 1질문 | 모든 사용자에게 같은 날 같은 질문 노출. | 타인 답변 매칭의 전제 |
| **P4** | 저장 시점 | 답변+배경은 **"카드 만들기" 클릭 시점에 확정 저장**. 이전 단계는 임시 상태. | 중도 이탈 데이터 오염 방지 |
| **P5** | 타인 답변 노출 | 같은 질문에 달린 타 답변 중 **무작위 1개** 노출. 한 번 뽑힌 답변은 그 질문에서 **고정**되어 재조회·새로고침에도 바뀌지 않는다. 사용자별 배정이며 1:1 대응은 아니다 — 같은 답변이 여러 사용자에게 배정될 수 있다. | 연결감·프라이버시 균형, ④⇄⑤ 왕복 시 답변이 뒤바뀌지 않도록 |
| **P6** | 콘텐츠 필터 | 제출 시 서버에서 금칙어 검사 후 차단. | 어뷰징·유해물 방지 |
| **P7** | 날짜 경계 | "서비스 기준 날짜"가 바뀌면 새 질문으로 전환. **기준 타임존은 KST(자정) 고정** — 사용자 로컬 시간과 무관하게 한국 시간 자정에 일괄 전환. | 일관된 날짜 동작 |

## 5. 사용자 플로우

### 5.1 신규(당일 미답변) 흐름
```
① 오늘의 질문 → ② 답변 작성 → ③ 배경 선택 → ④ 내 카드 → ⑤ 타인 답변
                                          (P4: 여기서 저장)      └ "내 카드 보기" → ④
```

> ⑤에서 ①로 돌아가는 "처음으로"는 두지 않는다(v1.1). 하루 1회 제약(P1)상 ①로 복귀해도
> 답변할 수 없어 막다른 길이기 때문이다.

### 5.2 진입 시 분기 (매 ① 진입마다 평가)
```
앱 진입(①)
 ├─ [체크A] 마지막 본 날짜 ≠ 오늘 ?
 │     └─ 예 → "새 질문 도착" 토스트 표시 후 '마지막 본 날짜' 갱신
 ├─ [체크B] 오늘 답변 기록 존재 ? (P1)
 │     ├─ 예 → ④ 내 카드(완료 상태)로 바로 이동. 질문 화면을 거치지 않는다
 │     └─ 아니오 → 질문 정상 노출 → 5.1 흐름 진입
```

### 5.3 화면 정의
| # | 화면 | 핵심 요소 | 주요 액션 |
|---|---|---|---|
| 1 | 오늘의 질문 | 오늘 질문 텍스트 | 답변하기 |
| 2 | 답변 작성 | 질문 재노출 + 입력칸 | 제출하기(→③) |
| 3 | 배경 선택 | 컬러/그라디언트/이미지 탭 + 실시간 미리보기 | 카드 만들기(→④, 저장) |
| 4 | 내 카드 결과 | 완성 카드. **완료 상태**(재진입)면 "오늘 답변 완료" 안내 + 다음 질문까지 카운트다운 추가 | 다운로드, 타인 답변 보기 |
| 5 | 타인 답변 보기 | 타 답변 1개 | 내 카드 보기(→④) |
| 토스트 | 새 질문 알림 | "새로운 질문이 도착했어요" | (자동 소멸) |

> ④는 "방금 만든 카드"와 "재진입 완료 화면"을 한 화면이 겸한다(v1.1). 별도 완료 모달을 두지 않는다.

## 6. 기능 요구사항 (실서비스 전환 기준)

와이어프레임에서 "브라우저 저장"으로 처리된 부분을 서버/DB 기준으로 재정의한다.

| 영역 | 목업(현재) | 실서비스 요구사항 | 우선순위 |
|---|---|---|---|
| 답변·배경 저장 | localStorage | 서버 DB 저장, 익명 식별자 단위, 날짜+질문 키로 관리 | **P0** |
| 질문 제공 | 코드 내 5개 하드코딩, 날짜 순환 | **운영자가 등록한 질문 DB에서 오늘 날짜 매칭 조회** (질문 약 20개 운영) | **P0** |
| 하루 1회 제한 | 브라우저 기록 | 서버에서 (익명ID + 날짜) 중복 제출 차단 | **P0** |
| 타인 답변 노출 | 고정 문구 1개 | 같은 질문 답변 중 무작위 1개 조회(본인 제외) | **P0** |
| 콘텐츠 필터 | 없음 | 제출 시 서버 금칙어 검사 후 차단 | **P1** |
| 카드 이미지 다운로드 | 알림창만 | 카드 영역 → 실제 이미지 변환·다운로드(html2canvas 등) | **P1** |
| 새 질문 토스트 | localStorage 날짜 비교 | 클라이언트 처리 유지 가능(서버 날짜 동기화 권장) | **P2** |

### 6.1 질문 운영 정책 (변경점)
- 목업의 "날짜 mod 질문수" 순환 로직은 **폐기**한다.
- 운영자가 등록한 질문 풀(약 20개)에서 **날짜에 매핑된 질문을 조회**하는 방식으로 전환.
- 질문 소진/재사용 정책, 노출 순서(순차/큐레이션) 정의 필요 → Open Issue.

## 7. 데이터 정의 (개념 모델)

> 백엔드 설계 입력용 개념 수준. 실제 스키마는 별도 설계.

- ~~**User(익명)**: 익명 식별자, 최초 진입일, 마지막 활동일~~ — **폐기.** 리텐션 지표(D1/D7)는
  GA4가 맡는다. 진입마다 갱신하던 탓에 부팅 시 주인 없는 행이 쌓였고 요청당 DB 왕복도
  1건 더 들었다. 익명 식별자는 쿠키가 단일 진실이며 Answer가 문자열로 참조한다.
- **Question**: 질문 ID, 본문, 노출 날짜(또는 노출 순서), 활성 여부
- **Answer**: 답변 ID, 익명 식별자, 질문 ID, 답변 본문, 배경 정보(타입/값), 작성일시
- **(파생) 타인 답변 조회**: 질문 ID 기준, 본인 답변 제외, 무작위 1건
- **타인 답변 배정**: 익명 식별자, 질문 ID, 배정된 답변 ID, 배정일시 — 첫 조회 시 뽑은 결과를 기록해 이후 고정 노출(P5)

핵심 제약:
- `(익명 식별자, 서비스 날짜)` 조합은 **답변 1건만 허용** (P1 보장).
- `(익명 식별자, 질문 ID)` 조합은 **타인 답변 배정 1건만 허용** (P5 고정 보장). 배정된 답변 ID에는 유니크를 두지 않는다 — 중복 배정 허용.
- 타인 답변 조회 시 **본인 답변 제외** 필수.

## 9. 범위 (Scope)

### 9.1 MVP 포함 (P0)
- 오늘 질문 조회(운영 DB 기반), 답변 작성, 배경 선택, 카드 생성·저장
- 하루 1회 제한(서버), 재진입 시 완료 카드 직행, 타인 답변 1개 노출

### 9.2 Fast Follow (P1)
- 콘텐츠 필터, 카드 이미지 다운로드

### 9.3 차기 (P2 이후)
- 새 질문 토스트 서버 동기화, 카드 보관함(과거 카드 모아보기), 공유 기능

### 9.4 명시적 제외 (Out of Scope)
- 로그인/회원 시스템
- 데모 전용 버튼(**⏭ 다음날로 이동, ⟲ 데모 초기화**) → 와이어프레임 테스트용, **실서비스 미포함**
- 답변 수정/삭제, 좋아요·댓글 등 소셜 기능

## 11. Open Issues (의사결정 필요)

1. **질문 운영 방식**: 20개 풀의 노출 순서(날짜 고정 매핑 / 순차 큐 / 큐레이션), 소진 후 재사용 여부.
2. **타인 답변 노출 정책**: 노출 후보 풀 범위(당일만 vs 누적), 본인 제외 외 추가 필터(최신성/품질) 여부.
   - 재조회 시 고정 여부는 **고정으로 확정**(v1.1, P5 참고). 위 두 항목은 여전히 미결.
3. **익명 식별자 방식**: 쿠키/로컬 토큰/디바이스 핑거프린트 중 선택과 그에 따른 유실·중복 트레이드오프.
4. **답변 미존재 시 UX**: 타인 답변이 0건일 때 5번 화면 처리.

> 서비스 기준 타임존은 **KST 고정으로 확정**되어 본 목록에서 제외함(정책 P7 참고).
